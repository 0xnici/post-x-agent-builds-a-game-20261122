# Video concepts — decided in-session by the agent

Bounty: "The agent builds a game from one prompt" (make.fun, post-x). Format: 1080x1920 vertical, 40.6 s. The only native asset is the video; therefore the video has to prove the whole story without narration from a human.

## Concept #1 — "Watch me type code" (DISCARDED — the cliché AI version)

A screen capture of a cursor racing through an editor, a compile bar, then the game appears. This is the default AI-demo cliché: it shows *typing speed*, not the one-prompt claim. It also buries the payoff — a judge has to wait to see a game at all. Discarded outright, per the house rule that concept #1 is the obvious AI answer and must never ship.

## Concept #2 — "Terminal beside arcade"

A permanent split screen: build log on one side, playable game on the other. Clear cause-and-effect, but at 1080x1920 both panels get small; the make.fun end card has to fight for space with two live scenes and the "one prompt" proof becomes a footnote.

## Concept #3 — "THE ONE-PROMPT RECEIPT" (CHOSEN)

A single vertical proof strip, like a receipt printed by the agent. Everything is stacked big, one thing at a time, in neon-on-near-black. The first five seconds are a rapid four-beat cut that shows the ENTIRE claim before the judge can scroll away; the remaining 35 s expands each beat into full-size, high-satisfaction footage.

The 5-second read (all four beats land before 00:05):

- **00:00–00:01.25 — PROMPT VISIBLE.** One chat bubble, one line: "Build me a neon Breakout game." A `1 PROMPT` stamp locks the claim. No code yet.
- **00:01.25–00:02.50 — AGENT WORKING.** A build log streams with ticking checkmarks: prompt read → game.html written → neon bricks → paddle physics → particles → autoplay test.
- **00:02.50–00:03.75 — FINISHED GAME RUNNING.** Real gameplay: bricks shatter, ball bounces, paddle tracks, combo counter climbs. A `PLAYABLE` badge.
- **00:03.75–00:05.00 — MAKE.FUN END CARD.** make.fun brand mark, referral `1n20pv53`, bounty URL, play code.

Because the end card appears *inside* the first five seconds and again at the close, the judge sees the referral/URL even if they stop watching early.

Expanded timeline after the receipt: 05–13 s the prompt types itself in at full size; 13–20 s the agent builds (progress bar to 100%, `BUILD COMPLETE`); 20–34 s the finished game runs uninterrupted with score/combo/particles and a `LIVE DEMO` tag; 34–40.6 s the full make.fun end card holds steady with referral code and bounty URL.

### Why #3 wins

It is the only concept where the proof ("one prompt → a real game → posted for make.fun") is legible in five seconds, and it is visually distinctive: a neon receipt aesthetic, not another IDE recording. Concept #1 is discarded, #2 is acceptable but cramped; #3 is executed.
